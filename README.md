# SPAR autoformalization pilot

This repository compares formalization methods on **one synthetic constitution benchmark**. The preliminary reference judgments are generated by independent Codex calls, with disagreement retained. No human annotation is required for the pilot.

**New design draft:** `data/benchmark-v2/` contains two paired, longer synthetic specifications and five shared cases. It has not been frozen or run. [The v2 audit and experiment update](docs/experiment-v2-update.md) lists the changes required before a new comparison. The commands below still run only the original pilot.

The first executable comparison uses Z3 and clingo on identical requirement bundles and case histories. The shared data format also records categories that either method may fail to express. Isabelle/HOL and nuXmv are listed as later integrations: a missing integration is reported as `not_run`, never as a semantic failure. The initial comparison cannot establish that agent judgments reflect a unique intended reading of the prose.

## Layout

- `data/requirements/`: one or two synthetic examples for each candidate category in the [requirements analysis](https://docs.google.com/document/d/1oIaNU9VJaiTLqQp7r9XSTWrpUL-WWTedCVUrdVeKe5Q/edit).
- `data/constitutions/`: six short bundles of interacting requirements.
- `data/development/` and `evaluation/heldout/`: shared cases. Cases have no embedded reference labels.
- `prompts/`: versioned instructions for formalization and independent judging.
- `src/autoform/`: orchestration, backend checks, scoring, and report writing.
- `runs/`: generated artifacts, reference votes, results, and manifests. This directory is ignored by Git.
- `reports/`: final analysis and findings.

## Reproduce

Install dependencies with `uv sync` or `pip install -e .`. Codex CLI must be available on `PATH` and authenticated. `autoform inventory` shows the frozen dataset. `autoform run --config configs/declarative-pilot.json` generates solver rules, collects independent agent judgments, evaluates each artifact, and writes a report. `autoform run --config configs/declarative-smoke.json` runs a smaller end-to-end slice. The earlier `configs/pilot.json` and `configs/smoke.json` use solver-backed Python and are retained as workflow baselines. `autoform report --run runs/<run-id>` regenerates the write-up from saved results.

Each Codex formalization call receives the relevant bundle, environment interface, two unlabeled development histories, prompt, and output schema. Reference votes are created after formalization and never included in the formalizer's prompt. Codex CLI may have broader filesystem read access on the host; this pilot relies on prompt-level separation and stage ordering rather than a security isolation guarantee. The runner copies its numeric summary to `reports/` and keeps complete traces and an agent draft in `runs/`. The checked research write-up is `reports/preliminary-findings.md`. See `docs/protocol.md` for the exact interpretation of results.

No experiment has been run merely by setting up this repository. The run commands invoke Codex and can consume model usage.
